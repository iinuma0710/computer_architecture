## シフト演算命令の定義
RISC-V には、SLL, SRL, SRA, SLLI, SRLI, SRAI の6種類のシフト演算命令が定義されています。
それぞれのアセンブリ表現は以下の通りです。

```assembly
sll  rd, rs1, rs2
srl  rd, rs1, rs2
sra  rd, rs1, rs2
slli rd, rs1, imm_i
srli rd, rs1, imm_i
srai rd, rs1, imm_i
```

SLL と SLLI は論理左シフト (Shift Left Logical)、SRL と SRLI は論理右シフト (Shift Right Logical)、SRA と SRAI は算術右シフト (Shift Right Arithmetic) です。
論理右シフトでは、シフト後の上位ビットが 0 になるのに対し、算術右シフトでは、シフト後の上位ビットがシフト前の最上位ビットで埋められます。

- SLL:  x[rd] = x[rs1] $<<$ x[rs2](4, 0)
- SRL:  x[rd] = x[rs1] $>>_u$ x[rs2](4, 0)
- SRA:  x[rd] = x[rs1] $>>_s$ x[rs2](4, 0)
- SLLI: x[rd] = x[rs1] $<<$ sext(imm_i)(4, 0)
- SRLI: x[rd] = x[rs1] $>>_u$ sext(imm_i)(4, 0)
- SRAI: x[rd] = x[rs1] $>>_s$ sext(imm_i)(4, 0)

SLL, SRL, SRA 命令は R 形式で、ビットアサインは以下の通りです。

| 命令 | 31-25 | 24-20 | 19-15 | 14-12 | 11-7 | 6-0 |
| :--: | :--: | :--: | :--: | :--: | :--: | :--: |
| SLL | 0000000 | rs2 | rs1 | 001 | rd | 0110011 |
| SRL | 0000000 | rs2 | rs1 | 101 | rd | 0110011 |
| SRA | 0100000 | rs2 | rs1 | 101 | rd | 0110011 |

一方、SLLI, SRLI, SRAI 命令は I 形式で、ビットアサインは以下の通りです。

| 命令 | 31-25 | 24-20 | 19-15 | 14-12 | 11-7 | 6-0 |
| :--: | :--: | :--: | :--: | :--: | :--: | :--: |
| SLLI | 0000000 | shamt | rs1 | 001 | rd | 0010011 |
| SRLI | 0000000 | shamt | rs1 | 101 | rd | 0010011 |
| SRAI | 0100000 | shamt | rs1 | 101 | rd | 0010011 |

R 形式命令では ```x[rs2]```、I 形式命令では ```shamt``` の5ビット値がシフト量となります。

val csignals = ListLookup(

## シフト演算結果の接続 @ EX ステージ
ID ステージで、シフト演算は ```ALU_SLL, ALU_SRL, ALU_SRA``` の3種類にデコードされるため、以下の3行を追記します。

```riscv/chisel/chisel-template/src/main/scala/Core.scala```
```scala
val alu_out = MuxCase(0.U(WORD_LEN.W), Seq(
    ...
    (exe_fun == ALU_SLL) -> (op1_data << op2_data(4, 0))(31, 0),
    (exe_fun == ALU_SRL) -> (op1_data >> op2_data(4, 0)).asUInt(),
    (exe_fun == ALU_SRA) -> (op1_data.asSInt() >> op2_data(4, 0)).asUInt(),
))
```

Chisel の左シフト演算子はビット幅をシフト領分拡張するので、下位32ビットを抽出して ```alu_out``` に出力します。
一方、右シフト演算は返り値が ```Bits``` 型であるため、シフト演算後に明示的に ```UInt``` 型に変換する必要があります。
