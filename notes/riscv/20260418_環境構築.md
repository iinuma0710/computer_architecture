# RISC-V 開発環境の構築
今回は RISC-V の開発環境を構築していきます。
Chisel と Verilog でコンテナを行ったり来たりするのは面倒なので、1つのコンテナで Chisel と Verilog の記述やシミュレーション、テストを実行できるコンテナを作成します。
ただし、FPGA の開発ツールについては、Vivado にせよ Quartus にせよ Docker 環境での利用が想定されていないことから、必要になったときに別途インストールすることにします。

## 全体構成とインストールするパッケージ
以下のようなディレクトリ構成で開発を進めていきます。

```
computer_architecture/riscv/
├── chisel/
├── verilog/
├── Dockerfile
└── docker-compose.yml
```

また、コンテナ内では以下のパッケージを準備します。

- [GTKWave](https://gtkwave.sourceforge.net/)
- [Icarus Verilog](https://github.com/steveicarus/iverilog)
- [sbt](https://www.scala-sbt.org/)
- [RISC-V GNU Compiler Toolchain](https://gtkwave.sourceforge.net/)
- [riscv-tests](https://github.com/riscv/riscv-tests)
- [Velirator](https://github.com/verilator/verilator)
- [Spike RISC-V ISA Simulator](https://github.com/riscv-software-src/riscv-isa-sim)

以降では、これらのパッケージについて詳しく見ていきます。


## GTKWave
GTKWave はオープンソースの波形ビューアで、Verilog の VCD ファイルなどを読み込んで波形を表示してくれます。
特段、バージョンは指定しなくてもよいかと思いますので、ほかのパッケージと合わせて ```apt``` でインストールしています。

```dockerfile
RUN apt update && \
	apt install -y ... gtkwave && \
    rm -rf /var/lib/apt/lists/*
```

## Icarus Verilog
Icarus Verilog は無料の Verilog HDL シミュレータです。
Verilog HDL のスーパーセットである SystemVerilog の構文にも一部対応しています。
メインの開発は SystemVerilog で進めるつもりなので、あまり使う機会はないかもしれませんが、とりあえず入れておきました。

```dockerfile
RUN git clone https://github.com/steveicarus/iverilog.git && \
    cd iverilog && \
    git checkout ${IVERILOG_VERSION} && \
    sh autoconf.sh && \
    ./configure && \
    make ${MAKEFLAGS} && \
    make install && \
    cd ${RISCV} && rm -rf iverilog
```

## sbt
sbt は "Simple Build Tool" の略で Scala のビルドツールです。
Scala で書いたプログラムを動かすときに必要になります。
インストールはダウンロードしたファイルを解凍して配置するだけで完了です。

```dockerfile
RUN curl -L https://github.com/sbt/sbt/releases/download/v${SBT_VERSION}/sbt-${SBT_VERSION}.tgz -o /tmp/sbt.tgz && \
    tar -xzf /tmp/sbt.tgz -C /opt && \
    ln -s /opt/sbt/bin/sbt /usr/local/bin/sbt && \
    rm /tmp/sbt.tgz
```

## RISC-V GNU Compiler Toolchain
RISC-V 向けの C/C++ クロスコンパイラです。
RISC-V で実装されている命令セットを指定してビルドする必要があります。
ここでは、RV32IMA (整数基本命令＋乗算命令＋アトミック命令) を指定しています。

```dockerfile
ARG RISCV_ARCH=rv32ima
ARG RISCV_ABI=ilp32

RUN git clone https://github.com/riscv/riscv-gnu-toolchain && \
    cd riscv-gnu-toolchain && \
    git checkout ${RISCV_GNU_COMPILER_VERSION} && \
    git config -f .gitmodules submodule.dejagnu.url https://gnu.googlesource.com/dejagnu && \
    git submodule sync dejagnu && \
    git submodule update --init --recursive && \
    unset CC CXX CPP CFLAGS CXXFLAGS CPPFLAGS LDFLAGS LD_LIBRARY_PATH && \
    ./configure --prefix=${RISCV_PREFIX} --with-arch=${RISCV_ARCH} --with-abi=${RISCV_ABI} && \
    make ${MAKEFLAGS} && \
    cd ${RISCV} && rm -rf riscv-gnu-toolchain
```

```git submodule sync``` や ```update``` を実行する際、dejagnu モジュールの参照先がハッシュを指定できずエラーになってしまうため、参照先を Google のミラーリポジトリに変更しています。

## riscv-tests
riscv-tests は RISC-V プロセッサ向けのユニットテストやベンチマークテストを集めたリポジトリです。
実装した CPU と一緒に使うものなので、ここではリポジトリからダウンロードしておくだけです。

```dockerfile
RUN git clone https://github.com/riscv/riscv-tests && \
	cd riscv-tests && \
    git checkout ${RISCV_TESTS_COMMIT} && \
	git submodule update --init --recursive && \
	cd ${RISCV}
```

## Verilator
Verilog や SystemVerilog のシミュレーションを行うための OSS です。
論理回路を C や SystemC にコンパイルしてシミュレーションを実行することができます。
役割としては Icarus Verilog と同じですが、SystemVerilog への対応状況を鑑みて、こちらをメインで使うことになると思います。

```dockerfile
RUN git clone https://github.com/verilator/verilator && \
    cd verilator && \
	git checkout ${VERILATOR_VERSION} && \
    autoconf && \
    ./configure --prefix=${RISCV_PREFIX} && \
    make ${MAKEFLAGS} && \
    make install && \
	cd ${RISCV} && rm -rf verilator
```

## Spike
オープンソースでデファクトスタンダードとなっている RISC-V の ISA シミュレータです。
シミュレーションが正しく実行された時の出力データを生成し、実装が正しいか否かの判定に利用します。
Verilator とセットで使用する想定です。

```dockerfile
RUN git clone https://github.com/riscv-software-src/riscv-isa-sim.git && \
    cd riscv-isa-sim && \
    git checkout ${SPIKE_COMMIT} && \
    mkdir build && cd build && \
    ../configure --prefix=${RISCV_DIR} && \
    make ${MAKEFLAGS} && \
    make install && \
    cd ${RISCV} && rm -rf riscv-isa-sim
```


## イメージのビルドとコンテナの立ち上げ
イメージのビルドにあたって ```docker-compose.yml``` を作成します。
```environment``` と ```volumes``` の ```/tmp/.X11-unix:/tmp/.X11-unix:rw``` は、GTKWave で GUI を利用するための設定です。

```yml
services:
  riscv:
    build:
      context: .
      dockerfile: ./Dockerfile
    container_name: riscv_container
    tty: true
    stdin_open: true
    privileged: true
    environment:
      DISPLAY: ${DISPLAY}
      QT_X11_NO_MITSHM: "1"
    volumes:
      - ./chisel:/work/riscv/chisel
      - ./verilog:/work/riscv/verilog
      - /tmp/.X11-unix:/tmp/.X11-unix:rw
```

下記のコマンドでイメージをビルドし、立ち上げたコンテナに入ります。

```bash
$ docker compose build
$ docker compose up -d
$ docker exec -it riscv_container /bin/bash
```

狙い通りのバージョンがインストールできていることを確認します。
GTKWave は特にバージョン指定していないので、時期によってバージョンが異なる可能性があります。

```bash
$ gtkwave --version
GTKWave Analyzer v3.3.116 (w)1999-2023 BSI

$ iverilog -V
Icarus Verilog version 13.0 (stable) (v13_0-dirty)

$ sbt --version
sbt runner version: 1.12.9

$ riscv32-unknown-elf-gcc --version
riscv32-unknown-elf-gcc (g5115c7e447f) 15.2.0

$ verilator --version
Verilator 5.046 2026-02-28 rev v5.046

$ spike --help
Spike RISC-V ISA Simulator 1.1.1-dev
```

## chisel-template のダウンロード
Chisel を使う際に便利なテンプレートとして、[chisel-template](https://github.com/chipsalliance/chisel-template) を利用します。
サブモジュールとして追加してもよいと思いますが、ここでは完全に自分のリポジトリに取り込むことにします。

```bash
$ cd riscv/chisel/
$ git clone https://github.com/chipsalliance/chisel-template
$ cd chisel-template/
$ rm -rf src/main/scala/* src/test/scala/*
```
